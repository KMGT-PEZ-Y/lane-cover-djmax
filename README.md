# Custom Lane Cover

리듬게임 레인 상단을 가려 아직 판정선에 도달하지 않은 노트를 시야에서 제거하는 오버레이
유틸리티입니다. 노트 밀도가 높은 채보에서 판정선 근처 노트 판별을 돕습니다.

- **드래그**로 위치 이동, 가장자리/모서리를 끌어 크기 조절
- **이미지 파일을 끌어다 놓아** 패턴 변경 (PNG/JPG/BMP/GIF/WebP/TIFF)
- 항상 **최상단 레이어** — 다른 프로그램 위를 가립니다
- 플레이 중에는 **마우스 클릭이 게임으로 통과**하고 포커스를 뺏지 않습니다

---

## 실행

### exe (권장)

`dist\CustomLaneCover.exe` 를 실행합니다. 설치 과정이 없고 단일 파일입니다.

> 첫 실행이 1~3초 늦게 뜰 수 있습니다. onefile 방식은 실행할 때마다 내부 파일을
> `%TEMP%` 에 풀어놓기 때문입니다. 폴더 형태로 쓰려면 아래 "빌드" 절을 참고하세요.

### 소스에서

```
python -m pip install -r requirements.txt
python main.py
```

## 사용법

프로그램을 켜면 **편집 모드**로 시작합니다. 점선 테두리와 8개 핸들, 좌상단 배지가 보입니다.

| 하고 싶은 것 | 방법 |
|---|---|
| 옮기기 | 본체를 드래그 |
| 크기 바꾸기 | 가장자리/모서리를 드래그 (최소 40×20) |
| 패턴 바꾸기 | 탐색기에서 이미지 파일을 창 위로 **끌어다 놓기** |
| 패턴 바꾸기 (대체) | 이미지를 클립보드에 복사한 뒤 `Ctrl+V` |
| 플레이 모드로 | `Ctrl+Alt+E` (또는 `Esc`) |
| 편집 모드로 | `Ctrl+Alt+E` |
| 표시/숨김 | `Ctrl+Alt+H` |
| 설정 창 | `Ctrl+Alt+S` |
| 종료 | `Ctrl+Alt+Q` |
| 1px 미세 조정 | 방향키 (`Shift`+방향키는 10px) |
| 크기 미세 조정 | `Ctrl`+방향키 |
| 10px 격자 스냅 | 드래그 중 `Shift` |

창 가장자리·중앙에 가까워지면 자동으로 붙습니다.

**편집 모드** — 크롬(테두리/핸들/배지)이 보이고, 마우스와 드롭을 커버가 받습니다.

**플레이 모드** — 크롬이 사라지고 클릭이 아래 프로그램으로 통과합니다. 이 상태로 게임을 합니다.

트레이 아이콘을 우클릭해도 같은 조작을 할 수 있습니다 (편집/플레이 전환, 표시/숨김, 설정, 종료).

### 설정 창

투명도, 맞춤 방식(늘리기/채우고 자르기/맞추고 여백/타일/원본 크기), 배경색, 컬러키 투명,
위치·크기 수치 입력, 전역 단축키 목록, 최상단 재고정 주기를 바꿀 수 있습니다.
설정은 `%APPDATA%\CustomLaneCover\config.json` 에 저장됩니다.

## 주의사항

### 독점 전체화면 게임 위에는 뜨지 않습니다

진짜 Direct3D 독점 전체화면에서는 DWM 합성이 우회되어 어떤 외부 창도 표시될 수 없습니다.
게임을 **전체화면 창 모드 / 테두리 없는 창 모드**로 설정하세요. 최신 게임의 "전체화면"은
실제로 borderless flip-model인 경우가 많아 그대로 동작하기도 합니다.

### 게임이 관리자 권한이면 단축키가 안 먹습니다

게임/런처가 관리자 권한으로 실행 중이면 Windows UIPI 때문에 `RegisterHotKey` 는 성공해도
`WM_HOTKEY` 가 전달되지 않습니다. 커버도 **같은 권한으로 실행**해야 합니다
(커버를 우클릭 → 관리자 권한으로 실행). 단축키가 갑자기 안 먹으면 이 경우를 먼저 의심하세요.
설정 창의 진단 항목에 어느 조합이 실패했는지 표시됩니다.

### 드래그 앤 드롭은 편집 모드에서만 됩니다

플레이 모드는 클릭이 통과되는 상태라 드롭도 함께 통과됩니다. 이는 의도된 동작입니다.
패턴을 바꾸려면 `Ctrl+Alt+E` 로 편집 모드로 돌아오세요.

### 안티치트

이 프로그램은 게임 프로세스에 **주입하거나 후킹하지 않습니다.** 창 배치, 전역 단축키,
트레이 아이콘만 사용합니다. 그래도 일부 안티치트는 외부 오버레이를 차단하거나 탐지할 수
있으므로, **사용 전 해당 게임의 정책을 반드시 확인하세요.** 사용은 본인 책임입니다.

### 최상단 재고정

게임이 전체화면 창 모드에서 최상단을 다시 가져가는 경우가 있어 기본 1초마다 최상단을
다시 주장합니다. 이 동작은 포커스를 뺏지 않습니다. 설정에서 주기를 바꾸거나 끌 수 있습니다.

## 빌드

```
python build.py              # 단일 exe (기본)
python build.py --onedir     # 폴더 형태 (시작 빠름, 백신 오탐 적음)
python build.py --clean      # build/ dist/ 지우고 새로 빌드
```

- `dist\CustomLaneCover.exe` (onefile) 또는 `dist\CustomLaneCover\` (onedir) 가 나옵니다.
- PerMonitorV2 DPI 매니페스트와 아이콘이 포함됩니다.
- 아이콘이 없으면 `tools/make_icon.py` 가 Pillow 로 자동 생성합니다.
- **Microsoft Store 판 Python**은 실행 파일이 0바이트 앱 실행 별칭이라 PyInstaller 가
  실패할 수 있습니다. 그 경우 python.org 정식 Python 으로 venv 를 만들어 빌드하세요.

## 진단 도구

```
python tools/smoke_test.py        # 소스 실행 스모크 테스트 (창/트레이/단축키/설정)
python tools/probe_win32.py       # Win32 제약 20개 실측
python tools/probe_clickthrough.py  # 실제 마우스 입력을 주입해 클릭 통과 검증
python tools/probe_recipe.py      # 클릭 통과에 필요한 ex-style 조합 실측
python tools/probe_hittest.py     # Tk 창 계층과 WindowFromPoint 동작 확인
```

`probe_clickthrough.py` 는 별도 프로세스를 아래 창으로 띄우고 **실제로 커서를 옮겨 클릭**해서
누가 입력을 받는지 확인합니다. 클릭 통과는 이 방법으로만 판정할 수 있습니다 —
`WindowFromPoint` 는 래퍼가 아니라 자식(TkChild)을 돌려주기 때문에 판정에 쓸 수 없습니다.

로그는 `%APPDATA%\CustomLaneCover\lanecover.log` 에 남습니다 (DPI 인식 수준, 단축키 등록 결과,
드롭 설치 실패 등).

## 구현 메모

Tk 8.6 과 Win32 의 상호작용에서 실측으로 확인한 것들입니다. 자세한 근거는
`lane_cover/native.py` 와 `lane_cover/app.py` 의 주석에 있습니다.

- **Tk 톱레벨은 HWND 가 두 개**입니다. `winfo_id()` 는 자식, `int(wm_frame(), 16)` 이 래퍼
  (진짜 톱레벨)입니다. z-order 와 ex-style 은 래퍼에만 유효합니다.
- 실제 계층은 **3단**입니다: 래퍼 → 톱레벨 창 → **Canvas 창**. 마우스와 드롭을 실제로 받는
  것은 **가장 깊은** 창이라, 입력을 걸 때는 항상 계층 전체에 겁니다.
- **Canvas 의 HWND 는 완전한 `update()` 전에는 없습니다.** 생성 직후에 드롭을 걸면 실제 대상이
  빠져 드래그앤드롭이 동작하지 않습니다. 그래서 상태가 바뀔 때마다 새로 생긴 창을 추가로 겁니다.
- **매핑 후 `overrideredirect` 를 바꾸면 래퍼가 파괴·재생성**됩니다. 그래서 매핑 전에 한 번만
  설정하고, 캐시한 HWND 와 서브클래싱이 무효가 되지 않게 합니다.
- **클릭 통과는 `WS_EX_LAYERED` 와 `WS_EX_TRANSPARENT` 가 둘 다 있어야** 성립합니다.
  `TRANSPARENT` 단독은 효과가 없습니다. 그런데 Tk 는 `-alpha` 가 1.0 이면 래퍼에 `LAYERED` 를
  켜지 않으므로, 그 경우 커버가 직접 켜고 `SetLayeredWindowAttributes` 로 알파를 걸어
  창이 사라지지 않게 합니다.
- **`-alpha` 를 처음 걸 때 Tk 가 ex-style 을 통째로 다시 써서** `WS_EX_TOOLWINDOW` 를 잃습니다.
  그대로 두면 Alt+Tab 에 나타나므로 매번 다시 주장합니다.
- **`WS_EX_LAYERED` 를 직접 켜면 창이 보이지 않습니다.** `SetLayeredWindowAttributes` 를
  반드시 함께 호출해야 합니다.
- 좌표는 **정수로만 저장**하고 `SetWindowPos` 로 복원합니다. Tk geometry 문자열은 선행 `-` 를
  "오른쪽/아래에서의 거리"로 해석해 보조 모니터에서 깨집니다.
